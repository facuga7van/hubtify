# Hubtify Mobile Strategy

**Date:** 2026-04-29
**Target:** Android only (no iOS)
**Framework:** Capacitor 8

## Architecture Decisions

### 1. Adapter Layer — Shared Business Logic (Option B)

Extract business logic from `electron/modules/*.ipc.ts` into `shared-logic/` package. Pure TypeScript, no platform deps. Both Electron and Capacitor consume same logic, only SQLite driver changes.

```
React Component → DataService → shared-logic → DatabaseAdapter
                                                  ├── ElectronDbAdapter (better-sqlite3)
                                                  └── CapacitorDbAdapter (@capacitor-community/sqlite)
```

### 2. SQLite Strategy

- **Mobile driver:** `@capacitor-community/sqlite` (native, actively maintained)
- **Interface:** `DatabaseAdapter` — async API. Electron wraps sync calls in Promise (zero cost)
- **Migrations:** Same SQL, shared runner, different adapter
- **WAL mode:** Supported on both platforms

```typescript
interface DatabaseAdapter {
  query<T>(sql: string, params?: unknown[]): Promise<T[]>;
  run(sql: string, params?: unknown[]): Promise<{ changes: number }>;
  execute(sql: string): Promise<void>;
  transaction<T>(fn: () => Promise<T>): Promise<T>;
}
```

### 3. Sync Conflict Resolution — Last Write Wins (LWW)

- **Creates:** No conflict. `randomUUID()` guarantees unique IDs on both devices.
- **Updates:** LWW by `updated_at` timestamp. Most recent wins.
- **Deletes:** Soft delete with `deleted_at`. Edit beats delete (conservative).
- **Append-only data** (habit checks, food logs): No conflict by nature.

**Required change:** Add `updated_at` column to ALL syncable tables. Update on every write.

### 4. Mobile UX / Navigation — Drawer Only

No bottom tabs. Drawer contains all modules + PlayerCard + settings. Scales to N modules.

```
┌─────────────────────────┐
│ ☰  Hubtify          🔔  │
├─────────────────────────┤
│                         │
│    100% content area    │
│                         │
└─────────────────────────┘

Drawer:
  PlayerCard (header)
  Questify
  Coinify
  Nutrify
  Cauldron
  [future modules...]
  ──────────
  Settings
  Sync
```

**Other mobile UX changes:**
- TitleBar (32px) → Android native StatusBar
- Large modals → Full-screen bottom sheets
- Tables → Card lists
- Cauldron timer → Android persistent notification
- Hover tooltips → Long-press
- Right-click → Long-press menus
- CSS: Media queries `@media (max-width: 768px)` for responsive

### 5. Monorepo Structure — Same Repo, Folders (Option B)

No workspaces. Minimal change to current structure.

```
electron/              main process (thin: IPC → shared-logic)
shared-logic/          NEW: pure TypeScript business logic
  db/                  DatabaseAdapter interface + migration runner
  modules/             quests.service.ts, finance.service.ts...
  rpg/                 rpg-engine.ts
src/                   React renderer (SHARED between desktop & mobile)
shared/                types (existing)
capacitor.config.ts    NEW: Capacitor config
android/               NEW: generated by Capacitor
```

Scripts:
```json
{
  "dev:desktop": "electron-forge start",
  "dev:mobile": "vite build && cap sync && cap open android",
  "build:desktop": "electron-forge make",
  "build:mobile": "vite build && cap sync"
}
```

## Key Codebase Facts (from analysis)

- Renderer has NO direct Electron API calls — all through `window.api.*`
- ~85% of preload methods are pure CRUD, portable
- Firebase/Firestore already cross-platform
- CSS uses variables + has breakpoints (needs mobile work)
- IPC pattern is clean and abstractable
- ~180 methods in preload.ts across all modules
- 39 user data tables in sync

## Migration Order (when ready)

1. Add `updated_at` to all syncable tables
2. Create `shared-logic/` with `DatabaseAdapter` interface
3. Extract business logic from `electron/modules/*.ipc.ts` → `shared-logic/modules/`
4. Refactor Electron IPC handlers to thin wrappers over shared-logic
5. Verify desktop still works identically
6. Init Capacitor, create `CapacitorDbAdapter`
7. Create mobile navigation (drawer)
8. Add responsive CSS breakpoints
9. Handle mobile-specific features (notifications, file access)
10. Test sync between desktop and mobile
